# 训练与数据集流水线（冻结）

## 冻结状态与执行模型违例

`app/api/train.py` 未挂载 → 全端点 404。但它**本身违反 ARCHITECTURE §6**：§6 要求训练走独立 CLI 或受控队列、**绝不**在 web 进程里长跑，而该 router 用 `BackgroundTasks` 在 web 线程池跑同步训练函数，`_training_tasks` 是进程内 dict（自带注释"生产环境应使用 Redis等"）。**只因未挂载才休眠——解冻它是带着违例上线**，必须先改成 §6 形状。合规路径是 `scripts/run_dataset_generation.py`（CLI + `MINIMAX_API_KEY` → `data/sft/training_data.jsonl`）。

## 数据契约

- `coordinate_prefix`：`[PAGE={p}][BBOX={x1,y1,x2,y2}] {text}`，float `%.2f`；**无合法 4 元 bbox 的样本被跳过**（§1 说"无法定位时返回 null"是指 live `vision_encoder` 输出记录，不是本序列化路径——ARCHITECTURE §1 把坐标前缀归给 vlm_tuner 的归属是**stale**：它是 SFT 侧，live 提取器是 `vision_encoder`）。
- DPO 规范化：`output`/`output_unsafe` → `chosen`/`rejected`，`instruction`+`input` → `prompt`；缺字段 `ValueError`、缺文件 `FileNotFoundError`、空文件即抛。`general_mix_ratio` 默认 0.15 混通用域。
- 自适应 KL beta 钳制 `[0.05, 0.3]`、target_kl 0.1。
- `filter_by_safety` 丢弃命中危险正则的样本，**除非** `is_dpo_negative`——DPO 负例故意保留不安全内容（`llm_expander.expand_safety_pair` 成对产 safe/unsafe 双胞胎）。

## 训练配置

QLoRA 默认：4-bit nf4、LoRA r=16/alpha=32 挂 q/k/v/o_proj；`train_projector` 解冻 projector/visual.merger/multi_modal_projector。任务状态机 `QUEUED→…→COMPLETED|FAILED|CANCELLED`，cancel 只翻标志位——**不真正中断**在跑任务。

## 数据与依赖边界

- `data/sft/` 只有 `.gitkeep`：训练数据、权重、患者数据**永不入库**（`data/sft/*.jsonl`、`data/augmented_*.json`、`output/` 均 gitignored）。
- `train` extra（torch/transformers/trl/vllm）**CUDA-only on Linux**——CPU 机器不要 `uv sync --extra train`。
- `scripts/fill_examination_and_metric.py` 是故意的安全占位符——旧版内嵌了 provider 凭据，现在无 env key 即拒绝、不带数据。

## 解冻危险清单

1. `train.py` 进程内 BackgroundTasks + 进程内任务表 vs §6 的 CLI/队列要求——重挂前先重写执行模型。
2. `train.py` 同样先于所有权/同意模型——无 auth（同 [consultation-pipeline](consultation-pipeline.mdx) 危险 1）。
3. `cancel` 不中断任务——别把它当停止语义暴露。
4. 坐标前缀的"null vs skip"语义在 SFT（skip）与 live（null）两侧不同，混用会写错样本。
