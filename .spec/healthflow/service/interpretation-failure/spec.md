# interpretation-failure

「一次解读为什么失败、这条命还有没有救、患者现在该做什么」此前由**四处互不同步的判定**
回答，患者只看得到其中一句：

1. `report.py` 的 `_TRANSIENT_ERROR_MARKERS`（14 个子串）对 `f"{filename}: {error}"` 做
   `in` 匹配——**文件名在被匹配的文本里**：把一份"没抽出指标"的体检单改名成 `timeout.jpg`，
   重试决策就翻转；而真正瞬时的故障（额度耗尽、限流）因为用词不在表里而**永不重试**。
2. `_parse_report` 的兜底把**任何**异常（数据库断连、目录不可用）包成
   `ParsedReport(success=False)`，与"这份报告本来就没读出指标"汇成同一条路——
   一个瞬时的基础设施故障，对患者永远表现为"请重新上传"。**这正是 ADR-0006 那次事故的形状。**
3. 成因被塞进两个 JSON 键，其中一半根本不出域。
4. 兜底文案在四层各写一遍，措辞已经分叉。

## raw source

本模块是**唯一**权威：五个成因、一个分类入口、以及由成因**派生**的两个读法
（是否可重试、患者侧动作）。

## 不变量

- 判定输入**优先取结构化事实**（HTTP 状态、异常类）；拿不到结构化事实时才看文本，
  且给出的仍是一个**具名成因**而不是一个布尔。
- **文件名不得参与判定**——第 1 条缺陷的成因就是匹配串里混进了文件名。
- 基础设施故障与"报告读不出指标"必须是**不同成因**，不得汇流。
- 本模块只 import 标准库（出域契约要读这份词表）。
