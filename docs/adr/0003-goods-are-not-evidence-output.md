# 商品不是证据输出

Status: Superseded in part by 0005

Supersedes: 0001

## Decision

HealthFlow 不在患者侧从**证据响应**读取商品，也不再由证据服务提供任何商品字段。

genesis-evidence 的 ADR 0006 把商品权威整体移到商城，`POST /api/evidence/matches`
不再返回 `recommendations`、`recommendation_message` 或 `product_status`。本仓的响应模型
是 `extra="forbid"`，因此两侧必须同批发布：本仓删掉商品字段的同时，证据服务必须已经停发。

**本决定有两个主语，它们的结局不同**（0005 分辨了这件事）：

- 「不展示任何商品」——**已被 0005 部分取代**。检测页展示商城返回的商品，但读取发生在
  服务端、与报告解读链路分离。取代它的理由写在 0005 的 Alternatives Considered 里
  （当初拒绝"本仓自行调商城"是因为那会耦合两个系统的展示决策；商品权威移到商城之后，
  展示决策只剩一方，耦合的前提不成立）。
- 「证据响应里没有任何商品字段」——**仍然有效，0005 不碰它**。它管的是证据契约的形状，
  与检测页从哪里取货无关。

## Alternatives Considered

- **保留商品字段的占位定义**：让契约看起来向后兼容。拒绝了——退役后这些字段恒为空态，
  留着只会让下一个读者以为商品仍由证据服务提供。
- **在本仓自行调用商城取商品**：把商品引进报告解读链路。拒绝了——那会把两个系统的
  展示决策耦合在一个页面里，且与"商品由商城按标签映射提供"的边界冲突。
  **（此条的前提已被商品权威的移动消解，0005 据此改判：检测页的商品由本仓服务端读取。）**
- **对历史数据用宽松读**：让旧报告继续可读。拒绝了——`extra="forbid"` 的价值正是挡住真实的
  契约漂移，为历史数据开一个永久例外会把那个价值一起丢掉。历史 payload 走一次性迁移。

## Rationale

边界跟着权威走。商品的租户、价格、库存与上架状态都在商城，报告解读服务对它们没有
判断力也不该有。把商品从这条链路里移走之后，本仓只剩一件事：把证据服务的输出如实
呈现给患者。

## Consequences

- **已评估的历史报告需要迁移**：删字段前持久化的 `evidence_result` 带商品字段，
  严格模型会让它们读不出来。迁移是一次性、可重复的操作。
- **商品侧的展示由商城负责**：报告解读页只呈现健康风险提示，不出现购物入口。
  **（0005 起检测页另有一块商品展示，读取在服务端；"展示决策归商城"这一点不变。）**
- **契约变更必须两仓同批**：任一仓单独发布都会让解析失败。
